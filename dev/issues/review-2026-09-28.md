# Code review, 2026-09-28

Findings from the first full review, before the initial release. Items are
referenced by id in commits and in the backlog. Delete this file once every
item is fixed or moved to `BACKLOG.md`.

Verified by experiment unless marked "by reading".

## Bugs

- **[fixed] B1.** `--as` with an unknown host name raises `KeyError` (`config.py`,
  `Config.pair`: `self.hosts[me]`). Must raise `ConfigError` like the
  `--remote` case does. Also reject `me == peer`.
- **[fixed] B2.** Autopush reports "diverged" when `origin` has no
  `remote.<name>.fetch` refspec. `git fetch origin <branch>` only updates
  `refs/remotes/origin/<branch>` when a refspec is configured; without it the
  ref is never created, both `is_ancestor` checks fail and the state becomes
  "diverged". Fix: compare with `FETCH_HEAD`, and fetch `refs/heads/<branch>`
  so a tag with the same name cannot be picked instead.
- **[fixed] B3.** Repository names are not escaped for Rich/Textual markup in
  `cli.show_plan` (table row), `cli.report` (failed line), `cli.report`
  (`config_note`, which can embed stderr), the spinner in `cli.make_plan`,
  `tui.ChoiceScreen.compose` (label) and `tui.PlanApp.on_mount` (row).
  `DataTable` parses markup in string cells (`Text.from_markup`). Status text
  is escaped; names are not.

## Robustness

- **[fixed] R1.** `session.run` only catches `CommandError`. `execute.copy_there`
  uses `tarfile.add`, so a file removed between plan and apply raises
  `FileNotFoundError`, aborts the whole run, skips remaining items and loses
  the track/ignore decisions. Catch `OSError` in `execute.apply` (or convert
  in the copy functions) and report it like a `CommandError`.
- **[fixed] R2.** No `ConnectTimeout` in `SSH_OPTIONS` (`hosts.py`). A powered-off
  peer hangs the program until the system TCP timeout. Add
  `-o ConnectTimeout=10`.
- **[fixed] R3.** ssh multiplexing only applies to `RemoteHost.wrap`. git `fetch`
  and `push` to `user@host:/path` use git's own ssh, so every out-of-sync
  repository opens a new connection and authenticates again.
  `docs/how-it-works.md` claims one connection per run. Fix: run peer git
  commands with `GIT_SSH_COMMAND` carrying the same control options.
- **[fixed] R4.** `ORIGIN_ENV` sets `GIT_SSH_COMMAND`, which overrides the user's
  `core.sshCommand` (used to pick a key for GitHub, for example). Read
  `git config core.sshCommand` and append `-o BatchMode=yes` to it instead
  of replacing it.
- **[fixed] R5.** `Host.python` does not handle non-JSON output (a noisy
  `/etc/profile` on the remote breaks it with `JSONDecodeError`). Convert to
  `CommandError` with the start of the output.
- **R6.** Config values are not type-checked (`depth = "3"`, a host table that
  is a string). By reading. Low priority.
- **R7.** Symlinked directories under `root` are skipped by the scanner
  (`follow_symlinks=False`). By reading. Document it.

## Design

- **D1.** Ignored-file copies overwrite without asking, including in
  `--auto`, with no backup. Decision: apply the same policy as for commits.
  Automatic only when the file is missing on one side. A file present on both
  sides with different content becomes a question (newer wins / skip); in
  `--auto` such items are skipped. Same-mtime-different-size stays a warning.
- **D2.** `gitpair plan` fetches into `refs/gitpair/*` and `refs/remotes/origin/*`.
  Keep the behavior, fix the README ("change nothing" is false): it never
  touches branches, work trees or origin.
- **D3.** `Action.KEEP` mixes "git action" with "extras only". Keep the enum,
  rename to `NONE` and describe it so the user sees the extras will run.
- **D4.** `plan.py` mixes pure decisions with network I/O (`compare`,
  `add_extras`, `plan_origin` fetch mid-decision). Split into two phases:
  gather facts (scans, ahead/behind counts, manifests, origin state) and
  decide with pure functions over those facts. `Item` should be built in one
  go instead of mutated by `info`, `mark_new` and `add_extras`.
- **D5.** New repositories (not in the config) get no extras on their first
  run (`mark_new` excludes `add_extras`). Acceptable; document.
- **D6.** One backup ref per branch, overwritten on every reset. The reflog
  already keeps the previous HEAD; say so in the docs.
- **D7.** No lock against simultaneous runs on both hosts (the forced push to
  `refs/gitpair/incoming` collides). Backlog.

## Code style (per the maintainer's Python guidelines)

- **C1.** Modules lack `__all__`; internal helpers have public names; the main
  API is not first. `plan.py` exposes ~20 same-level functions where the API
  is `build`, `describe`, the dataclasses and the enums. Same for `execute.py`
  (`apply`) and `config.py` (`load`, `update_repos`, `Config`).
- **C2.** Functions lack docstrings; none documents the exceptions it raises
  (`CommandError`, `ConfigError`); pure helpers (`compare_files`, `count`,
  `remote_path`) should carry doctests; single-argument functions should use
  positional-only `/`.
- **C3.** `Item` has too much mutable state with implicit invariants
  (`in_sync`, `comparable`, `choice`, `new`, `options`). Follows from D4.
- **[fixed] C4.** `--as` and `--remote` are only accepted before the subcommand
  (`gitpair plan --remote c3po` fails). Use a shared parent parser or move
  them to the subcommands.

## Tests

- **T1.** Real git repositories and state assertions are the right strategy;
  keep `World` and `FakeRemote`.
- **T2.** Missing pure unit tests: `compare_files` (hypothesis: every name
  lands in exactly one of the three lists or is equal on both sides),
  `find_repos` (depth, `SKIP_DIRS`, hidden, symlink), `describe`, `remote_path`.
- **[fixed] T3.** Missing regression tests for B1, B2 (origin without refspec), B3
  (repo name with `[`), R1, R5.
- **T4.** Optional integration test against `ssh localhost` behind an
  environment variable, so `run_binary`, `host:/path` URLs and the config copy
  run through the real path at least sometimes.

## Repository and docs

- **P2.** False claims: "change nothing" (D2) and "one TCP connection" (R3).
- **P4.** `release.yml` needs a GitHub environment `pypi` and a PyPI trusted
  publisher; list both steps in `CONTRIBUTING.md`.
- **P5.** No `docs` task. Open.
- **S2.** fish as the remote login shell is fine: `shlex.join` output was
  tested under `fish -c` with quotes, backslashes, `$HOME` and `~`. Only a
  literal `\\` inside single quotes differs. Document, do not fix.
- **S3/S4.** The `data` tar filter strips group/other write bits; `tar -x` on
  the remote follows pre-existing directory symlinks. Both inside the trust
  model; mention in `docs/configuration.md`.
